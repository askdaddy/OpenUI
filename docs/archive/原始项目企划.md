# OpenUI 设计规范 v1.0 —— 现代化扁平设计章节

**明确表态：现代化（扁平化）不只是 OpenUI 的"目标之一"，它应该被升格为 OpenUI 的**身份**——你之前的直觉"浮夸靠可配置，简洁是默认"，恰好是当前 Forever 生态里被验证有效的差异化路线。PlayerUIWoW 用"现代扁平 + 剥离狮鹫/羊皮纸 + 1px 边框 + 类图标替代头像"这套语言在 CurseForge 站稳了脚跟，Shade UI 用"原生基础上加现代暗色"的克制路线被独立评测认可，这两条路线你都可以借鉴，但 OpenUI 必须在这两条之间找到属于自己的第三条路——下面给你一套可以直接落地的设计语言。**

## 一、为什么把扁平化升格为身份而非目标

Forever 现有 UI 生态的位置可以用一张谱系图看清：

```
原生暴雪 ←—→ Shade UI（原生+暗色皮肤）←—→ OpenUI ←—→ PlayerUIWoW（全面扁平重绘）←—→ EllesmereUI（全家桶）
              ↑ 轻改派                                ↑ 重绘派
```

- **Shade UI 路线**：尽量保留原生暴雪结构，只做暗色皮肤和 utility 增强。优点是兼容性好、维护轻；缺点是"浮夸"程度有限，对你想要的视觉表达不够
- **PlayerUIWoW 路线**：彻底剥离羊皮纸/狮鹫/厚边框，全扁平重绘，配 Color Picker 全局调色。优点是视觉冲击力强、辨识度高；缺点是重绘面广，每帧都要维护
- **OpenUI 应该走的第三条路**：**模块级扁平重绘**——每个模块（地图/任务/QoL/窗口）的 UI 按扁平语言从零设计，但不试图接管动作条/头像框/名牌这些暴雪核心（那是 EllesmereUI 的领域）。这样既拿到现代视觉的辨识度，又守住"简洁为底、可浮夸可选"的克制底线，同时避开全家桶的维护负担
这条路线的差异化价值：**当用户想要 PlayerUIWoW 的视觉冲击，但只想要地图和任务这两块、不要被全套绑架时——OpenUI 是唯一选项。**

## 二、设计原则（可落地版）

| 原则 | 具体含义 | 对标 |
| --- | --- | --- |
| **零装饰** | 不用羊皮纸、狮鹫、金色 filigree、渐变阴影堆叠；一切视觉表达靠**色块 + 边框 + 留白** | PlayerUIWoW、ForeverUI 的"no stone frames"哲学 |
| **扁平暗色为底** | 默认深灰底（`#181B22` 系），用透明度而非纯黑制造层次；所有面板统一 alpha | Shade UI 的"dark theme feel" |
| **职业色做点缀** | 血/蓝/能量条按职业色渲染，主 UI 仍是中性灰；这是"免费的辨识度" | ElvUI 一贯做法 |
| **信息密度克制** | 默认只显示必要信息，hover/展开才出现细节；"看得到但不打扰" | Poulpix UI Immersive 的 minimal HUD 思路 |
| **一致性压倒一切** | 间距/字号/边框宽度/圆角全部从 token 表取，不允许模块各自定义 | 8pt grid / 4pt grid 设计系统标准 |
| **浮动效果可选** | "浮夸"靠主题开关：边框颜色、强调色、动效、光标特效；默认全部关 | ElvUI WindTools 的 theme + color opacity 思路 |

## 三、设计 Token 表（Core/Style.lua 的内容）

这是整个扁平语言的技术落地，**所有模块禁止在代码里硬编码视觉常量**，统一从这张表取。设计 token 的核心理念是"**把设计决策抽离成名字 → 值对**"，让改一处即全局更新。

### 3.1 间距 Token（4pt Grid）

采用 4pt 网格而不是 8pt，因为游戏 UI 元素通常比 Web UI 更紧凑，4pt 提供更细的步进：

```lua
OpenUI.Spine.spacing = {
    xs  = 4,     -- 极小间距：图标与文字间隙
    sm  = 8,     -- 元素内边距、行间距
    md  = 12,    -- 模块内分块间距
    lg  = 16,    -- 模块间、面板内边距
    xl  = 24,    -- 面板之间、主分区间距
    xxl = 32,    -- 顶级容器间距
}
```

**约定**：所有 margin/padding/gap 都必须是这 6 个值的倍数或本身，出现 5/7/10 这类"自然数"即为 bug。

### 3.2 字号 Token

```lua
OpenUI.Spine.typography = {
    caption  = 10,   -- 辅助说明、时间戳
    body     = 12,   -- 正文、默认
    label    = 14,   -- 按钮文字、字段标签
    title    = 16,   -- 面板标题、模块名
    heading  = 20,   -- 主面板标题
}
```

- 中英双档：中文在相同字号下视觉更满，所以**中文版本 `body` 和 `label` 各 +1px**（13/15），由 Locales 检测 `GetLocale()=="zhCN"` 自动切换
- 全部带 `outline: THICK` 描边，保证在任何背景上可读

### 3.3 颜色 Token（语义命名）

按语义命名而非具体色值命名（"primary" 而非 "blue"），这样换主题只改值不改名：

```lua
OpenUI.Spine.color = {
    -- 表面（背景层次）
    surface0     = {r=0.09, g=0.10, b=0.13, a=0.85},   -- 主面板底
    surface1     = {r=0.12, g=0.14, b=0.17, a=0.85},   -- 次级面板
    surface2     = {r=0.16, g=0.18, b=0.22, a=0.85},   -- 卡片、条目底
    
    -- 文字
    textPrimary  = {r=0.95, g=0.95, b=0.95, a=1},     -- 主文本（≥4.5:1 对比）
    textSecondary= {r=0.65, g=0.68, b=0.72, a=1},     -- 次级说明
    textDisabled = {r=0.45, g=0.48, b=0.52, a=1},
    
    -- 边框
    border       = {r=0.30, g=0.33, b=0.38, a=0.90},   -- 1px 标准边框
    borderHover  = {r=0.55, g=0.58, b=0.62, a=0.90},   -- hover 态
    
    -- 强调（浮夸感的调节阀）
    accent       = {r=1.00, g=0.65, b=0.20, a=1},      -- 主强调（暖橙）
    accentSoft   = {r=1.00, g=0.65, b=0.20, a=0.35},   -- 半透明强调
    
    -- 语义色
    success      = {r=0.30, g=0.78, b=0.44, a=1},
    warning      = {r=1.00, g=0.80, b=0.10, a=1},
    danger       = {r=0.92, g=0.30, b=0.28, a=1},
}
```

**对比度合规**：所有文字与背景的对比度按 WCAG 2 AA 级要求校验——普通文字 ≥ 4.5:1，大字号（≥18pt 或 14pt bold）≥ 3:1。上面 `textPrimary` 对 `surface0` 的对比例约 12:1，`textSecondary` 约 6.5:1，都安全。
**主题切换**：Theme 模块提供两档预设——

- `Minimal`（默认）：`accent` 用冷灰蓝（{r=0.55, g=0.70, b=0.95}），整体克制
- `Flashy`：`accent` 切换为暖橙、允许光标特效/动效；其余 token 不变（结构一致性不动摇）

### 3.4 边框与圆角

```lua
OpenUI.Spine.corner = {
    width   = 1,   -- 标准边框 1px（虚屏下会自动适配）
    radius  = 4,   -- 默认圆角 4pt
    pill    = 999, -- 胶囊按钮用
}
```

- **避免纯直角和过圆角**：4pt 是当前扁平设计的甜点值，太直会硬、太圆显得像移动 App
- 圆角通过 `MaskTexture` + 内置圆角 atlas 实现，不画额外贴图

## 四、扁平化的 WoW 引擎技术实现

WoW 引擎的 UI 渲染是 Canvas 模型（无 DOM 无 CSS），扁平语言的每种效果都有对应的引擎 API：

| 设计效果 | 引擎 API | 说明 |
| --- | --- | --- |
| 扁平色块面板 | `texture:SetColorTexture(r, g, b, a)` | 比 SetTexture 更轻、永不模糊 |
| 渐变背景 | `texture:SetGradient("HORIZONTAL", c1, c2)` | 用于条形（血/蓝/XP）自然过渡 |
| 1px 边框 | Frame 自带 `SetBackdrop({edgeSize=1, edgeFile=...})` | 或用 4 个 1px Texture 拼 |
| 圆角 | `MaskTexture` + 内置圆角 atlas | 对内容做 mask，边缘干净 |
| 半透明层 | 颜色 alpha 通道 | surface0/1/2 靠 alpha 区分层次，不是不同灰度 |
| 描边文字 | `FontString` 的 outline 属性 | THICK/OUTLINE 两档 |
| 状态条纹理 | 自绘 1px 宽的线性贴图 | 比暴雪默认的斜纹贴图更干净 |
| 现成图标 | `texture:SetAtlas("name")` | 调用暴雪内置 Atlas 系统，几乎零自绘 |
| 悬停动效 | `OnEnter/OnLeave` + `texture:SetAlpha()` | 简单透明度过渡，避免耗性能的 Lerp |
**Sprite 约定**：

- 自绘贴图必须是**2 的幂**（16×16 / 32×32 / 64×64 / 128×128 / 512×512），避免引擎缩放采样错误
- 优先用暴雪 Atlas（几千个现成图标/边框/职业图标/Currency 图标），只有 Atlas 无法表达时才自绘
- 所有自绘贴图放 `Media/textures/`，按模块分文件夹（如 `Media/textures/quest/`）

## 五、以 MapEnhance 模块为例的落地样例

这是 OpenUI 第一个模块的设计落地方案，可以看出"扁平语言"如何具体到像素：

### 5.1 视觉规格

```
┌─────────────────────────────────────┐
│  ✦ Map Enhance            [—][×]   │  ← heading 20pt, textPrimary
├─────────────────────────────────────┤
│  ●  飞行点            ♦  商人       │  ← body 12pt
│  ●  训练师            ♦  旅店       │  ← surface2 卡片
│  ●  拍卖行            ♦  修理       │  ← 8pt 行距
├─────────────────────────────────────┤
│  [ 简洁 ] [ 浮夸 ]     [保存]       │  ← label 14pt 按钮
└─────────────────────────────────────┘
   ↑ surface0 主面板，4pt 圆角，1px border
```

- 面板底：`surface0`（alpha 0.85），无渐变、无阴影
- 列表项卡片：`surface2`，圆角 4pt，hover 时边框变 `borderHover`
- 图标：全部走 `SetAtlas("Vehicle-Air-Lock")` / `SetAtlas("Banker")` 这类内置资源，不自绘
- 行间距：8pt（`sm`）
- 分区上下：16pt（`lg`）
- 按钮文字：`label` 字号，主按钮 `accent` 背景 + `surface0` 文字，副按钮 `surface2` 背景 + `textPrimary`

### 5.2 对比参考

- **暴雪原生同面板**：羊皮纸背景 + 金色 filigree 边框 + 狮鹫装饰 + 3 层嵌套渐变阴影 —— 信息密度一样但视觉负担重
- **PlayerUIWoW 同面板**：扁平暗色 + 1px 边框 + 类图标点缀 —— 已经接近，但它是"全面重绘"路线
- **OpenUI 版本**：相同扁平语言 + 4pt 网格 token + 语义颜色 + 主题切换 —— 可以做到"看起来比 PlayerUIWoW 更克制，但同样有辨识度"

## 六、避坑清单（扁平化在 WoW 里特有的坑）

| 坑 | 表现 | 应对 |
| --- | --- | --- |
| **半透明叠加陷阱** | 多层 alpha 面板嵌套后看起来"糊"，文字对比度跌到 3:1 以下 | 同一层级禁止两层 alpha >0.5 的面板叠加；文字层必须是不透明层 |
| **缩放失真** | 自绘贴图在非 1.0 UI Scale 下出现 1.5px 模糊边框 | 用 2 的幂尺寸 + 9-slice 边框（`edgeFile` + `tileSize`） |
| **对比度违规** | 深灰底配深灰字，弱光环境下不可读 | 所有 token 在 Lite 主题和 Dark 主题下都跑一次 WCAG 校验 |
| **中文渲染溢出** | 同一 FontString 在英文下 14pt 够用，中文下溢出或换行 | 中文 body/label 自动 +1px；容器高度预留 +2px 缓冲 |
| **类色污染** | 职业色做强调色后，暗色底上某些职业色（深蓝术士/暗红 DK）对比度不足 | 职业色只用于 2px 边框或图标，不用作文字色；文字统一走中性灰 |
| **动效滥用** | "浮夸"主题下加太多 OnUpdate 动画导致 FPS 下跌 | 动效只允许 `OnEnter/OnLeave` 触发的单次过渡，禁用 OnUpdate 持续循环 |
| **Atlas 名称硬编码** | 客户端 patch 改 atlas 名后整片 UI 报错 | `IconLib` 模块封装所有 atlas 引用，失败时回退到 `SetTexture([[Interface\Icons\...]])` |
| **9-slice 边框用错** | 边框纹理没有 tile 信息，拉伸后边缘被拉断 | 自绘边框必须配 `pkgmeta` 里标注 tile 信息，且在 1px/2px 两档测试 |

## 七、关于"浮夸"可配置性的边界

你之前说的"简洁&浮夸"实际上是一个**主题光谱**，OpenUI 应该把它做成三档而不是二档，给用户更细的控制：

| 主题 | 边框 | 强调色 | 动效 | 目标用户 |
| --- | --- | --- | --- | --- |
| **Minimal**（默认） | 1px 中性灰 | 冷蓝，低饱和 | 无 | 想要干净不打扰的玩家 |
| **Balanced** | 1px，hover 时 accent | 中饱和强调色，仅按钮/图标用 | hover 透明度过渡 | 大多数玩家 |
| **Flashy** | 2px accent 边框 + 外发光（backdrop bg） | 高饱和强调色，可用于背景 tint | hover 滑动过渡 + 光标特效 | 想要"看着爽"的玩家 |
**主题切换的工程实现**：Theme 模块只负责覆盖 token 表的值（**不是改逻辑**），所有模块在 `OnProfileChanged` 时重新读取 token 并刷新。这是设计 token 系统最大的红利——**换主题 = 改一张表，不动任何模块代码**。

**一句话收尾**：把扁平化升格为 OpenUI 的身份，你手里就有了三件 Ruyi 没有的东西——一张 token 表让它长期视觉一致、一套扁平语言让它有辨识度、一个主题光谱让它同时满足"简洁&浮夸"的两种状态。这三件东西加起来，就是 Forever 生态里目前还没有人完整交付的那条差异化路线。
