状态：B0–B5 排序已由用户确认为继续细化的基线；具体窗口、交付范围与发布门槛未冻结，不授权编码，不含工期承诺。

## 排序依据

已确认：以升级、日常、副本均衡的综合玩家为基准；按使用频度排序；分批发布；同频度下允许依赖先行，但需解释并确认。

下表频度为产品判断，尚无用户行为统计。基础能力排在首位是依赖建议，不是声称设置窗口比战斗界面使用更频繁。模块可独立使用指不强制启用其他功能模块；是否依赖共同核心、如何打包另行决定。

## 已确认排序基线

| 批次 | 建议覆盖 | 使用频度判断与依赖原因 |
| --- | --- | --- |
| B0：共用基础与首个可用批次 | 设置、搜索、本地化、主题控件、配置档、诊断；动作条与聊天 | 共用能力支撑所有后续模块，建议先行；动作条常驻、聊天跨场景高频，作为首批实际界面验证基础能力 |
| B1：常驻战斗与导航 | 玩家/目标等单位框体、施法条、光环、名牌、小地图、提示框与基础提示 | 覆盖持续可见的信息；依赖 B0 的风格、配置和模块生命周期；单位框体为此前范围外新增规划项，默认开关待确认 |
| B2：升级与日常高频窗口 | 背包/银行/公会银行、世界地图、任务日志/追踪、任务对话与交付、NPC 对话、拾取、商人/修理 | 升级与日常反复使用；候选安排晚于常驻界面仅是频度判断，需用户确认；地图导航和资源记录的增强范围单列 |
| B3：角色、组队与社交 | 角色装备/属性、法术书、原生天赋界面替换、队伍/团队框体及管理、好友、公会、组队/PvP、交易、邮件 | 角色成长与副本组织使用；原生天赋界面替换已确认纳入，额外天赋模拟器仍排除 |
| B4：专业、经济与系统 | 专业/配方、拍卖行、声望等成长窗口、游戏菜单、游戏设置、按键绑定、帮助与通用确认弹窗 | 相对场景化的候选后续项；通用弹窗与系统入口若被前批次依赖，需列明原因后调整顺序 |
| B5：特殊场景与覆盖补全 | 宠物及特殊控制界面、飞行交通、特殊任务/载具等目标构建实际存在的界面，以及盘点遗漏项 | 使用受玩法影响较大，需按客户端真实可用项补齐；不能以此批次作为遗漏高频窗口的理由 |

B0–B5 的相对排序已确认；各批是待细化窗口组，不代表一批必须同时交付全部窗口；若拆分，需用户确认。

## 工具与增强的安排

用户已决定先完成核心界面替换，再做工具增强，不采用穿插交付工具的提案。一键钓鱼、装备比较、目标距离、雷达、副本计时、经验计量、猎人喂宠、按钮停靠栏等仍属于需求范围，但后置交付；它们之间的顺序另行确认。

“核心界面替换完成”具体对应哪些批次或窗口，尚需用户确认，不能据此擅自判定全部 B0–B5 完成前都禁止增强，也不能擅自提前工具。

地图服务标记、导航、飞行进度、资源记录和窗口布局增强同样需要区分“界面替换”与“额外能力”，各自注明交付批次。禁用弹窗继续仅作研究。

原生天赋窗口的自有界面替换已确认纳入覆盖；额外天赋模拟器继续不做。B3 中原有待确认表述以此结论为准。

## 候选发布门槛（未批准）

- 已交付模块可单独启停；关闭后按明确流程恢复原生界面。
- 英文、简体中文、语言回退与手动切换可用。
- 已交付设置支持约定的共享配置、导入导出和默认恢复。
- 替换界面的核心游戏操作可用，未实现部分与未覆盖窗口明确列出。
- 验证对应的战斗限制、脱战/重载行为、缩放、错误与空数据状态。
- 新模块接入不要求用户启用其他功能模块；共同基础依赖明确。

实际验收用例与哪些门槛适用于哪一批，待模块规格和客户端研究完成后由用户确认。
