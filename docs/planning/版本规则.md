# 版本规则

[文档导航](../README.md) · [变更记录](../../CHANGES.md) · [决策记录](决策记录.md)

## 已确认

用户指定格式：`<YYYY>.<MM>.<patch>-<PreRelease>+<Build>`。主段为年份，次段为月份；patch、预发布与构建信息按规定管理。此前 0.x.y 提案不采用。CHANGES 仅按版本记录已落地的代码变化。

## SemVer 对照

[SemVer 2.0.0](https://semver.org/spec/v2.0.0.html) 要求版本核心数字不能有前导零；预发布与构建字段使用点分隔的 ASCII 字母、数字或连字符，预发布的纯数字字段也不能有前导零。预发布低于同核心的正式版，构建信息不影响优先级；标准允许省略预发布和构建字段。

年月含义属于本项目的日历版本约定，不表达标准 SemVer 主次版本的 API 兼容含义。兼容性、配置迁移和破坏性变化仍需单独说明，不能从年月推断。

## 已确认递增与记录方式

- 年份四位；月份为 1–12，不补零。
- 年月按发布月份确定；跨月 patch 归零，同月每个新正式发布递增 patch，例如 `2026.11.0` → `2026.11.1` → `2026.12.0`。
- 开发阶段使用 `dev.N`，测试阶段允许 `alpha.N`、`beta.N`、`rc.N`；正式版省略预发布后缀。
- 仅在有真实构建时追加 `+Build`，否则省略；不编造构建编号或提交 SHA。
- 当前规划版本为 `2026.11.0-dev.1（未发布）`，不表示已有可用插件或构建。
- 后续已落地的代码变化集中追加到 CHANGES 当前待发布版本；准备发布时确认完整版本并冻结记录，发布后变化归入下一待发布版本。
- CHANGES 不记录设计讨论、规划、决策或纯文档调整；设计结论保留在模块规范与决策记录。一次关联代码变更可合并记录，不按每次文件写入递增版本。

## 仍待审定

- Build 的来源、生成时机与格式。
- 预发布序号在跨阶段、跨核心版本时的起点及重置细则。
- 若待发布周期跨月，应在发布准备时按已确认年月规则核对版本；更名和记录归档的具体流程待后续发布方案确认。

配置数据格式版本独立管理，不能将年月版本直接当作配置兼容性判断。
