# 全界面覆盖规划

[返回 README](../../README.md) · [总体规划](项目规划.md) · [模块与默认启用](模块索引.md) · [待决策](决策记录.md)

## 已确认原则

- 规划覆盖游戏内全部 UI，不以前述首版功能清单为范围上限。
- 按使用频度排开发顺序。
- 排序画像为综合玩家：升级、日常、副本均衡。
- 分批发布，每批完成的模块可独立使用。
- 同等使用频度下，允许共用基础能力和依赖模块先行；必须标明依赖与调整原因，供用户确认。
- OpenUI 自行设计可见布局和风格，允许复用客户端基础控件、经过筛选的模板及必要安全机制。
- 整个模块可以关闭，关闭后允许回到原生界面。
- 当前仅规划与文档，不编写实现代码。

## 候选盘点框架

以下为避免漏项的分类草案，不是完整窗口清单、已确定开发顺序，也不保证目标构建存在每项能力。应核对本机 Forever 后补充具体窗口、子状态与访问条件。

| 类别 | 待核对对象举例 |
| --- | --- |
| 常驻与战斗 | 动作条、玩家与目标等单位框体、队伍团队、名牌、施法条、光环、提示信息、错误提醒 |
| 信息与导航 | 小地图、世界地图、任务日志与追踪、导航、飞行与交通界面 |
| 物品与角色 | 背包、银行、公会银行、角色装备、属性、装备比较、法术书、天赋、宠物 |
| NPC 与交易 | 对话、任务接受交付、商人、修理、拾取、交易、邮件、拍卖行 |
| 成长与制作 | 专业、配方、技能、声望及其他在目标客户端可用的成长界面 |
| 社交与组队 | 聊天、好友、公会、组队、团队管理、查找队伍、PvP 相关界面 |
| 系统与反馈 | 游戏菜单、设置、按键绑定、帮助、确认弹窗、进度反馈、过场或特殊交互 |
| OpenUI 自有界面 | 统一设置、配置档管理、导入预览、诊断、布局编辑及工具窗口 |

## 每个窗口的盘点字段（草案）

- 目标构建中是否存在、如何打开、有哪些状态与子窗口。
- 主要使用场景、访问频率、屏幕常驻程度；排序口径需用户确认。
- 自有界面替换范围、核心行为、数据来源与安全限制。
- 默认启用状态、模块关闭后的原生恢复条件。
- 与其他界面的依赖，以及语言、主题、配置共享与导入导出要求。
- 里程碑与验收条件：正常、空数据、错误、战斗、缩放和中英文等状态。

## 尚待决策

- 常驻界面与高频打开窗口如何比较；各具体界面的顺序需确认。
- 全面覆盖分多少批、每批确切边界与发布门槛；候选顺序见 [分批交付草案](交付路线.md)。
- “游戏内全部 UI”的边界：系统设置、帮助、特殊场景等逐项确认；登录与角色选择界面不擅自归入可替换承诺。

候选批次仅为讨论稿，不将估计频度当作实测统计，不将建议顺序当作项目决策。
