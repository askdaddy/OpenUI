## 从参考归纳的组织原则

Ruyi 和 ElvUI 都采用 TOC/XML 的显式加载顺序、语言与默认配置分离、功能分组和共同基础；ElvUI 额外拆出按需设置包与库包。成熟项目存在不同取舍，没有唯一必须照搬的目录。

## 打包方案对比

| 方案 | 收益 | 成本 |
| --- | --- | --- |
| 单一 OpenUI 插件包，内部模块化 | 安装与发布简单，配置与版本一致，适合从零逐批完善 | 设置代码若全部加载可能增加启动开销；需维护模块资源启停与显式加载 |
| OpenUI 核心 + 设置 + 可选库插件包 | 可独立按需加载设置，依赖边界更显式 | 多 TOC、安装完整性和版本协调更复杂，库包是否值得拆需实际依赖支撑 |

建议先采用单包内部模块化；只有实际启动成本、体积或依赖证明需要时，再讨论拆包。该建议未批准，不决定是否采用 Ace3、oUF 或其他库。

## 单包候选结构（打包根已确认，其余待审定）

```text
OpenUI/                     # 安装包根，发布时直接放入 Interface/AddOns（D53）
  OpenUI.toc                # 元数据、SavedVariables、显式加载入口
  Init.lua
  Core/                     # 初始化、生命周期、事件、客户端适配
  UI/                       # token、主题、通用控件
  Locales/                  # 英文、简体中文
  Config/                   # 默认值、配置 schema/迁移；不依赖设置窗口加载
  Settings/                 # 设置展示、导航、搜索、编辑与预览
  Modules/                  # 各界面模块，按规模拆分内部文件
  Tools/                    # 后置工具，与界面替换分组
  Media/                    # 有来源与许可记录的字体、纹理、声音
  Libs/                     # 仅在批准第三方库后出现
README.md / AGENTIC.md / CHANGES.md / .gitignore   # 仓库根文档
docs/                       # 文档、模块规格与参考资料
examples/                   # 本地参考，不提交、不打包
tests/                      # 后续必要自动检查与可复现用例，命名待审定
scripts/                    # 后续打包/检查脚本，确有需要才建
```

打包时以仓库根的 `OpenUI/` 目录为根，不把 examples、开发脚本与历史材料一起装进游戏。根目录“只保留 README”约束指文档入口；源码及工具目录不是额外根文档。

## 加载与模块边界建议（未批准）

- 依赖层建议为初始化 → 已批准库 → 本地化/配置基础 → 核心与 UI → 模块/设置注册 → 启动；具体先后需按实际依赖定，不照抄任何参考清单。
- 不以目录名代替模块生命周期；每模块明确注册、启用、停用、配置刷新、事件/计时器释放与原生恢复。
- 模块内部配置声明可共置还是集中 Config 尚待决定；无规模需要时不强制每模块创建固定数量空文件。
- 设置页不决定代码模块数量；共享控件不依赖业务模块；运行数据与导出配置分离。
- 仅 Forever，不预置其他客户端分支；需要特殊能力判断时集中适配并记录证据。
