## 三个不同层次

| 层次 | 内容 | 与视觉统一的关系 |
| --- | --- | --- |
| 显示与布局 | 面板、按钮外观、字号、配色、间距、信息组织和交互反馈 | 可以由 OpenUI 统一设计，不要求沿用暴雪外观 |
| 客户端控件与模板 | Frame、Button、Texture、FontString，以及可复用模板和行为 | 创建自有界面仍需使用客户端提供的 UI 能力；复用模板不必等于复用其装饰，具体模板需核实 |
| 游戏数据与受保护交互 | 背包数据、施法、目标操作、动作条状态等 | 插件通过客户端允许的接口接入，不能因重画界面就绕过权限和战斗限制 |

“完全自有 UI”可定义为玩家可见的布局和风格由 OpenUI 掌握，而不是重新实现游戏引擎、施法或物品系统。该边界已由用户确认。

## 例子与约束

- 动作按钮可以采用自有布局、边框与文本，同时把施法等行为接到客户端允许的安全按钮机制。不能把普通点击回调当作任意受保护操作的替代通道。
- 背包窗口可以重做分类、布局和视觉，但物品移动、使用和银行访问仍依赖客户端允许的交互。
- 战斗中受保护界面的结构或配置更改可能受限；不承诺所有设置随时即时生效。哪些修改延后、何时重载需要逐模块核实并决策。
- 关闭模块恢复原生界面已经确认；能否立即恢复、是否需要脱战或重载尚未确认。
- 不必依赖现成第三方 UI 插件来获得统一外观。是否使用通用库、是否集成其他插件是另外的技术与产品决策。

## 参考证据与适用限制

- [客户端 UI 源码镜像中的 SecureTemplates.lua](https://github.com/tekkub/wow-ui-source/blob/live/FrameXML/SecureTemplates.lua)：可见安全按钮通过属性描述动作；用于说明安全交互机制，不证明当前 Forever 构建的完整行为。
- [客户端 UI 源码镜像中的 EditModeManager.lua](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_EditMode/Shared/EditModeManager.lua)：可见安全执行与战斗锁定条件分支。
- [SharedUIPanelTemplates.xml](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_SharedXML/Mainline/SharedUIPanelTemplates.xml)：可见可复用模板也包含具体装饰，因此不能不加筛选地继承后声称已去除原生外观。

这些是不同分支的客户端源码参考，不是与本机 70888 匹配的验证基线。Forever 的实际模板、接口限制和可替换程度，仍按 [客户端研究](../references/Forever客户端.md) 继续核实。
