## Ruyi 1.0.9

- 来源：`examples/Ruyi/Ruyi.toc`，声明 Version 1.0.9、Interface 16001；不能由此替代本机运行验证。
- 加载：TOC → Init → Libs → Locales → Config → Core → Modules → Plugins；各目录 XML 明确文件次序。
- `Core/Modules.lua` 提供注册、初始化、错误收集与任务生命周期；`Config/Config.xml` 分离模块默认配置与字段。
- 可借鉴：模块有入口、配置有归属、显式加载次序、任务启停与错误归属。不直接沿用增强原生视觉的产品方向，也不把整个 GUI 和所有业务都堆进 Core。
- 许可证观察：本地 LICENSE 将 Lua/XML/TOC 标为 Apache-2.0，其余文档、数据和图片标为 CC BY 4.0；嵌入资源还可能有独立声明。这里只记录原文件声明，不授予 OpenUI 复制许可，也不据此确定 OpenUI 许可证。

## ElvUI 16.01

- 来源：`examples/elvui-16.01/` 三个插件包的 TOC 均声明 v16.01。
- 核心 `ElvUI` 依赖 `ElvUI_Libraries`；`ElvUI_Options` 依赖核心并声明 LoadOnDemand，设置包不存储配置档。
- `ElvUI/Game/load_forever.xml` 明确语言、默认配置、Core、模块、平台差异与各窗口皮肤的加载次序；`Game/Shared/Modules/load_modules.xml` 将动作条、名牌、地图、单位框体等分组。
- 可借鉴：设置展示与配置存储分离，基础能力与业务分离，大型模块内部拆分，按需加载有明确边界，平台差异集中管理。
- 不照搬：OpenUI 仅考虑 Forever，不需要先建多客户端目录树；ElvUI 的局部皮肤处理不等于 OpenUI 已决定采用相同替换策略。
- 本地 LICENSE.txt 是自定义许可，含保留权利与公开传播限制；本轮仅研究组织方式，不复制代码、字体、图像或整体文件。第三方库须单独检查其许可证。
