# LSM 分发评估

[文档导航](../README.md) · [主题与控件计划](../modules/主题与控件.md) · [决策记录](../planning/决策记录.md)

状态：2026-11-12 方案比较；用户批准双向媒体共享，但要求先比较维护与许可成本再决定分发方式。未添加依赖或打包脚本。

## 方案对比

| 方面 | 安装包内嵌 LSM 与必要依赖 | 可选集成，使用运行环境已有 LSM |
| --- | --- | --- |
| 用户安装 | 一次安装即可获得双向互通 | 无 LSM 时需用户另装提供它的包，或媒体互通不可用 |
| 功能一致性 | 可携带已验证基线，但运行时仍可能由其他插件注册更高库修订 | 依赖外部版本和加载时机，环境组合更多 |
| 维护 | 维护固定来源、版本、更新审查、打包清单及回归 | 不维护分发副本，但仍维护能力检测、加载通知与无库降级 |
| 验证 | 需要仅安装 OpenUI、与其他版本共存、加载先后的测试 | 需要无库、库过旧、延迟出现、其他提供者关闭的测试 |
| 许可工作 | 核对所选具体副本及依赖的分发权、声明、来源和修改记录；素材另行核对 | 不分发库副本可减少该部分打包工作，但不能代替素材授权与自身适配代码审查 |
| 自有 UI | 应能使用自身媒体，不应因外部媒体缺失失去基本界面 | 同样需要自有基础媒体和明确回退，不能将可选库当作隐含必需依赖 |

这是相对成本判断，尚未实测安装包大小、内存或加载时间。可选集成不意味着无维护成本；嵌入也不保证独占或强制运行所带库版本。

## 许可证据与不确定性

- 本地 ElvUI 16.01 与本机 DBM-Core 嵌入的 LSM 源文件头部标注 `LGPL v2.1`，且声明依赖 LibStub 与 CallbackHandler-1.0。
- [LSM 官方项目页](https://www.wowace.com/projects/libsharedmedia-3-0) 当前元数据却显示 All Rights Reserved，与本地文件头声明不同。本轮未取得拟选正式发行包的完整许可链，不能仅据其中一项批准再分发。
- [LibStub 官方说明](https://www.wowace.com/projects/libstub) 声明 Public Domain，并提供嵌入方式。
- [CallbackHandler 官方说明](https://www.wowace.com/projects/callbackhandler) 提供插件嵌入步骤；这不代替所选版本随附许可证。ElvUI 的 Ace3/LICENSE.txt 是另一个包内的许可文件，不能不加核对地套到独立 CallbackHandler 副本。
- 资源字体、纹理和声音与库代码是不同来源；发布清单应逐项记录许可及必要声明，不将 LSM 注册等同于素材再分发授权。

本节记录来源声明和待核实事项，不作“采用 LSM 就要求整个 OpenUI 改用某许可证”等未经核实的推断。OpenUI 自身许可证仍待用户决定。

## 推荐与决策门槛

推荐在核清所选正式版本分发许可、验证 Forever 基线后，将其与必要依赖嵌入安装包，以符合开箱即用目标；保持原样、记录来源和版本，避免私有修改分叉。不需要因此引入整套 Ace3，也不决定单包或多包结构。

如果具体版本的分发依据仍不明确，可先采用可选集成方案，不分发不明副本；其无库体验必须明确。该备选不能自行取代用户选择。

实施前应形成：所选发行版与源码来源、许可证与声明、依赖清单、是否修改、运行时库版本识别及共存测试方案。完成后由用户决定嵌入或可选集成。本轮推荐并非已批准分发决定。
